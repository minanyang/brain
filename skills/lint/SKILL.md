---
name: lint
description: Use when the user asks whether the vault or wiki is healthy, wants a health report, or asks about stale conflicts, orphan pages, unlinked names, or digests that were never ingested; also on a weekly cadence.
argument-hint: "[--vault <name>] [--fix]"
allowed-tools: Bash(${CLAUDE_PLUGIN_ROOT}/scripts/resolve-vault.sh *), Bash(${CLAUDE_PLUGIN_ROOT}/scripts/lint.sh *), Bash(${CLAUDE_PLUGIN_ROOT}/scripts/finish.sh *), Bash(git show *), Read, Edit, Glob, Grep
---

Produce a report. Do not edit anything unless the user passed `--fix` or asks for a specific fix afterwards. The schema is injected at session start inside a vault; if you are not in one, read `${CLAUDE_PLUGIN_ROOT}/docs/schema.md` for what the rule numbers mean.

1. Find the vault: `"${CLAUDE_PLUGIN_ROOT}/scripts/resolve-vault.sh" [--vault <name>]` prints `name<TAB>path`.
2. Run the deterministic rules: `"${CLAUDE_PLUGIN_ROOT}/scripts/lint.sh" <path>`. Its output is self-labelled (rules 1, 2, 3, 5, 7, 8) and ends with the inputs for the two judgment rules. If it reports `(no ingest history yet)` for rule 7, say so rather than treating it as a pass.
3. Rule 4 — names on three or more pages with no page of their own: from the page list in the report, grep the wiki directories for recurring proper nouns (people, teams, services, repositories, tools) that appear on at least three pages and have no page. A name counts as having a page when it matches a page's file name, its `title:`, or an alias in the vault's `CLAUDE.md` glossary — read the glossary first, because it also records the names that deliberately have no page. Cluster before reporting: names that are facets of one thing — six slash commands of the same workspace, four services of one system — are one missing page, not six findings. Report the cluster, the pages it appears on, and the page you would create. Never report a name the glossary already maps; that is where nearly every false positive comes from. Skip generic words, tool names a topic page already covers, and digest tags.
4. Rule 6 — drift between `brief.md` and Claude's built-in memory: read each memory file listed in the report and compare it with the brief. A contradiction is the same subject with incompatible claims — a different owner, status, date or preference for the same thing. A fact present on one side only is not a contradiction, and neither is different phrasing. The test is consequence: would a session that read only the brief act wrongly? "Went live in production" for a system deployed for internal testing only is a finding; "ships weekly" versus "released every week" is not. Note that the memory listing spans every project on this machine, including ones that route to another vault.
5. Print the combined report: the script output, then your rule 4 and rule 6 findings, then one line with the total, script findings plus your own. One line per finding, shaped `rule N | <file> | <what>`, ordered by what it costs the human — rule 7 first (a lost human claim), then 6, then 1, then the hygiene rules. A first lint over a vault of about sixty pages usually returns eight to twelve findings, mostly rules 3 and 4; that is normal, not a crisis.
6. Fix, only with `--fix`, and only what has one obviously correct outcome: an orphan page an existing page plainly should link to, or a rule 7 claim restored verbatim with `git show 'brain/last-ingest^:<page>'`. Never bump a stale `updated:` date — the staleness *is* the finding, and moving the date hides it without re-verifying anything. Never hand-edit `index.md`, `brief.md` or `log.md` to clear a finding: they are generated from the pages, so fix the page and let the next run regenerate them. Conflicts are never fixed here; they are the human's call through `/brain:ingest`. Say what you changed.
7. Record the run: `"${CLAUDE_PLUGIN_ROOT}/scripts/finish.sh" --vault <path> --op lint --note "<N> findings"` — add `--add <page>` for each page you changed under `--fix`. It regenerates `index.md` and `brief.md` and commits even on a report-only run — which is how a stale generated file stops being a finding. If `resolve-vault.sh` exits non-zero there is no vault for this directory: say so and offer `--vault <name>`.
